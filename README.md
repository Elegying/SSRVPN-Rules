# SSRVPN 规则

仅发布分流数据，不包含客户端源码、节点订阅或用户信息。

- `lists/direct-apps.json`：安卓默认直连应用。
- `lists/proxy-apps.json`：安卓默认代理应用。
- `latest/version.json`：客户端检查的签名版本索引。
- `snapshots/版本号/`：不可变的完整快照。

在 GitHub 编辑应用名单的精确包名即可；版本可以手动提高，内容变化而版本未提高时，发布程序会自动递增该组件版本。两份名单不得重叠，通用浏览器不得加入。安卓应用名单优先于手动规则：国内名单应用从系统 VPN 排除，国外名单应用强制代理；未命中名单的流量再按手动规则和公共规则分流。智能和全局模式均遵循此顺序，浏览器仍按目标分流。

工作流每日同步一次 Loyalsoldier/clash-rules 的直连、代理、GFW 和国内 IP 数据，固定本次来源提交；数据变化且检查通过才签名发布。补充规则来自 SSRVPN 既有人工审核基线，来源包括 MetaCubeX/meta-rules-dat。保留上游许可证与来源记录；数据遵循其来源许可证，本仓库按 GPL-3.0 分发。

异常大小、数量突变、语法错误或关键目标检查失败时，停止发布并保留旧快照。需要撤回时恢复正确源内容并发布更高版本，不编辑历史快照。

客户端每次启动后的首次连接两分钟后检查一次，静默下载变化文件，下次连接启用。下载失败继续使用本地数据。国外应用识别依赖 Android 10+，识别失败时内核流量按访问目标分流；国内应用的系统 VPN 排除不依赖该查询。

发布凭据 `RULE_SIGNING_KEY` 只保存在仓库 Actions Secret；客户端只有公钥。维护者需关注工作流失败；本流程不保证任何目标在所有网络实时可达。

安卓磁贴冷启动和原生恢复沿用上次受保护连接配置；下载的新快照在 App 生成下一次连接配置后进入磁贴快照，避免新旧名单混用。
